# 迁移和设置核验

## 盘点结果如何支持决定

先列占用最大的相关项，写清“实际路径、占用、是什么、建议和影响”。需要分级时用三类：可核实为可再生的候选项；需要本人选择的下载、离线内容或项目材料；保持保护的系统、配置和运行中数据。不能只看扩展名、目录名或旧时间就分为可删；例如安装包可能是唯一离线副本，名为Cache的目录也可能有账户或离线数据。先确认具体内容，再给出相应操作。

目录有包含关系时不重复相加，扫不到或无法归属的占用单列，不能算成可清理空间。分别记录预估可释放、跨盘迁移和实测余量变化；回收站、链接或仍被使用的文件可能让逻辑大小与实际释放不同。不为让磁盘柱状图“对齐”而把未知量分给垃圾。

分析和报告默认只读；需要文件报告时用静态内容，不因提供图表而附带删除接口或启动清理服务。用户已经批准的具体操作按原范围执行，无须因风险分级重新询问；范围、冲突或影响改变时再确认对应项。

## 普通目录

预先记录源、目标、大小/文件数、可用余量、锁定状态与授权。源和目标不得互相包含；输出清单不放到被扫描目录里。保留原目标内容，同名差异单独处理。复制之后核对文件内容与必要空目录，确认源未在复制期间变化，再决定获准的移除。

Windows链接、目录联接和重解析点可能跳到目录外，不能简单递归跟随。遇到它们记录并停下相关项；附带脚本明确拒绝这些对象，不能仅因工具没扫描它们就宣布迁移完整。

计数和字节总量一致不等于内容一致；哈希验证能补充内容证据，但对正在写入的数据库应采用应用原生迁移与相应验收。跨盘直接Move-Item可能留下部分移动状态，先检查两边，再在批准范围内补齐，不能反复重试直到误删残留。

本脚本只核对文件内容与目录存在性，不核对访问权限、时间戳等文件属性。任务要求保留这些信息时，在复制方案中补充相应核验，不能仅凭内容哈希通过就把其他属性也写为通过。

## 批量操作与中断恢复

批量任务保留每项“原路径 → 新路径 → 实际动作与结果”的简短记录，包含已复制、已核验、已移除或跳过及原因；单个文件不必套完整表格。项目目录按资源引用关系处理，不因按扩展名分类而拆散项目；整理布局与腾出磁盘空间分别记录。

中断后先核对源、目标、原清单和当前设置，再继续尚未完成的项目，不按旧计划盲目重复移动或删除。源有变化时重新核验；目标冲突或超出已批准范围时停止对应项并提出具体选择。恢复只针对本次实际完成的动作，保留原来就存在的目标文件和后续无关设置。

## 应用原生迁移

使用应用当前版本的入口。记录迁移前位置与可核验数据，等待它完成，观察迁移后路径、旧目录、会话/文件和合理样本；应用正常运行本身不证明全部历史消息已核验。数据库日志/WAL或诊断日志变化要与用户内容分开解释，缺失项不能不报告。

## 保存路径与日志设置

记录原值和恢复方法。Windows默认目录、浏览器偏好和软件接收/备份路径分别验证；新配置可能需要下一次启动，实际写入应在批准的正常使用场景中检查，未检查则留为未验证。日志清理周期、数字枚举和级别均以本机版本为准，不写死某版Clash数字。

## 清理

核对最终绝对目标在已批准目录内，不跨壳组合删除命令，不依据模糊通配符覆盖整棵AppData。跳过活动/锁定文件；回收站移动具有恢复性但不等于已腾出空间，清空需要对应批准。恢复时只还原本次相关设置；旧完整配置备份不能直接覆盖后续更改。
