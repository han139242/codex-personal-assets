# 迁移和设置核验

## 普通目录

预先记录源、目标、大小/文件数、可用余量、锁定状态与授权。源和目标不得互相包含；输出清单不放到被扫描目录里。保留原目标内容，同名差异单独处理。复制之后核对文件内容与必要空目录，确认源未在复制期间变化，再决定获准的移除。

Windows链接、目录联接和重解析点可能跳到目录外，不能简单递归跟随。遇到它们记录并停下相关项；附带脚本明确拒绝这些对象，不能仅因工具没扫描它们就宣布迁移完整。

计数和字节总量一致不等于内容一致；哈希验证能补充内容证据，但对正在写入的数据库应采用应用原生迁移与相应验收。跨盘直接Move-Item可能留下部分移动状态，先检查两边，再在批准范围内补齐，不能反复重试直到误删残留。

## 应用原生迁移

使用应用当前版本的入口。记录迁移前位置与可核验数据，等待它完成，观察迁移后路径、旧目录、会话/文件和合理样本；应用正常运行本身不证明全部历史消息已核验。数据库日志/WAL或诊断日志变化要与用户内容分开解释，缺失项不能不报告。

## 保存路径与日志设置

记录原值和恢复方法。Windows默认目录、浏览器偏好和软件接收/备份路径分别验证；新配置可能需要下一次启动，实际写入应在批准的正常使用场景中检查，未检查则留为未验证。日志清理周期、数字枚举和级别均以本机版本为准，不写死某版Clash数字。

## 清理

核对最终绝对目标在已批准目录内，不跨壳组合删除命令，不依据模糊通配符覆盖整棵AppData。跳过活动/锁定文件；回收站移动具有恢复性但不等于已腾出空间，清空需要对应批准。恢复时只还原本次相关设置；旧完整配置备份不能直接覆盖后续更改。
